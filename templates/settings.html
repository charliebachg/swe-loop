Rerun a shard the repository and the store, together

Running the loop again on a shard that is already fixed would show nothing: the sessions would find the work done. A reset puts one shard back to its broken state. On the repository, its files return to the base branch as it was before any fix landed{% if rerun.baseline %} (commit {{ rerun.baseline }}){% endif %}, the change is committed and pushed to {{ rerun.repo }} {{ rerun.base }}, and the old repair branch is deleted. In the store, every row about the ticket is snapshotted to a file and forgotten. The issue stays open, so the next Run on Automations picks it up as new and does the whole loop again for real.

{% if rerun.willPush %}live: the clone at {{ rerun.clone }} is restored and pushed{% elif rerun.live %}live, but no clone at {{ rerun.clone }}: only the store is reset{% else %}replay: only the store is reset; the repository is not touched{% endif %}

Offer it again is for showing the merge step without waiting for a run. It takes the change that was already verified, puts the branch back to before it landed, and opens the same commit as a new pull request. No session is spent and the AI is asked for nothing.
